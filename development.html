Development

Kite is written in Rust, with its interface in QML using Kirigami, on top of QtWebEngine. It's modelled on Falkon and reads Falkon's bookmark and history formats.

Source code Issues Developer docs

Building

You need:

  • Rust, through rustup
  • Qt 6.9 or newer, with QtWebEngine (Core and Quick runtime)
  • Kirigami (KDE Frameworks 6)
  • qqc2-desktop-style
git clone https://github.com/n4n0GH/Kite.git
cd Kite
cargo build --release
./target/release/kite            # --profile NAME, --private, --debug

Running the tests

cargo test --workspace
node --test crates/kite-core/src/webext/js/*.test.js crates/kite/qml/*.test.js crates/kite/plugins/*/*.test.js

Building an AppImage

packaging/appimage/build-appimage.sh            # → dist/Kite-<version>-<arch>.AppImage
packaging/appimage/build-appimage.sh --no-build # bundle an existing target/release/kite

The script downloads linuxdeploy and its Qt plugin on first use, then asks whether to keep the result in dist/ or install it for your user.

How it's put together

crates/kite-core
Pure Rust, unit-tested, no Qt: history, bookmarks, sessions, search and address bar logic, site settings, downloads, content blocking, privacy features and the WebExtensions runtime.
crates/kite
The application: the QML interface and its bridge to QtWebEngine and Plasma.

The developer docs covers the architecture in detail, where each part of the interface is defined, and how to write native plugins.

Contributing

  • Found a bug? Check the FAQ, then open an issue with your distribution, Plasma version and steps to reproduce it.
  • Want to fix something? Fork the repository and open a pull request. Run the tests first.
  • Kite keeps a log of warnings and errors in ~/.local/share/kite/logs/<profile>/kite.log (the run before is kite.prev.log), and after a crash a report in last-crash.txt. Attach them to bug reports. Addresses from private windows are scrambled in both.
  • Page or console output goes to the terminal with RUST_LOG, which helps when reporting problems with sites or extensions.
  • kite --debug shows tools for looking into Kite. For now, the lists Dangerous Sites checks against, and how an address is checked (Settings → Browsing).
